# 原文默写改造: 保留句 + 单空 + 输入判分

## Goal

改造原文默写题: 每句(对句)挖一个分句保留另一半、答案全部单分句(去双空)、横线处可输入答案并自动判分(容错标点),答错自动进错题本。

## Requirements

### R1. 数据改造 (raw moxie.json 原文默写题型)
- 规则: 对句拆两分句(按逗号/顿号/分号),保留一个、挖一个;挖空位置交替(前/后分句),避免规律呆板;每篇至少保留 1 个完整句不挖。
- 单分句答案: answers 每项 = 一个分句;blanks = 分句数;q 重写(保留分句原文 + ___ 占位,标点完整)。
- 源: learning.json 原文对齐 + 现有 answers 推导;无原文/无法对齐的题保留原状并记录。
- 理解性/词义/译文默写不改(答案保持现状)。

### R2. 交互改造 (MoxieArticle.tsx + moxie.css)
- 原文默写题: 每个 ___ 渲染为输入框(横线样式);输入内容本地 state 保存。
- "对答案" → 自动比对(忽略首尾空白/标点/全半角;支持多个等价答案?) → 对: 绿色成功态;错: 显示参考答案 + 自动 addWrong 进错题本(保留现有"答错进错题本"语义)。
- 其他题型(理解性/词义/译文): 可输入或保持"显示答案+自评"以设计为准(推荐统一为输入,若工作量过大则仅原文默写支持输入)。
- qid/进度存储不变。

### R3. 校验与测试
- validate 新增段: 原文默写题断言(answers 无空格分隔多分句、q 中含保留句文字、每篇 ≥1 完整句)。
- test:flow 默写流程适配新交互(输入→判分→错题本)。
- 数据改造后 `npm run data:build` + validate 全绿。

## Acceptance Criteria

- [ ] 全部原文默写题: answers 单分句(无 "A B" 双内容);每句保留一个分句;每篇 ≥1 完整句
- [ ] 输入框可输入,对答案自动判分,容错标点;答错自动进错题本
- [ ] validate 新断言通过;check + test:flow 全绿
- [ ] 进度存储兼容(旧 qid 语义不变)

## Notes

- 数据重写脚本放 scripts/moxie/ 或一次性脚本,产出记录到 research/rewrite-record.md(改动篇目/题数/保留句样例)。
- 无法对齐原文的题: 记录后保留原状,不臆造。
