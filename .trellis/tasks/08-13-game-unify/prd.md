# 文言文闯关游戏整合: 消灭"学习/默写"字眼, 学习+默写模块深度并入关卡体系

## Goal

把整个项目糅合成一个统一的**文言文闯关游戏**：UI 中不再出现"学习"和"默写"两个词（学习→历练、默写→默诵），并把"课文全解"(learning) 与"默写训练"(moxie) 两个平行模块**深度结构整合**进统一的"关卡工作区"。用户从闯关地图进入任意篇目，阅读、鉴赏、考点、注释、默诵训练全部在一个关卡页内完成，整体观感就是一个闯关游戏。

## 背景

- 应用现状：Vite+React+TS SPA，已有闯关地图(/map, 142关卡)、XP/连击/成就(游戏化已于 08-12 上线)，但**学习模块(/articles)与默写模块(/moxie)仍是两套平行页面**，且大量旧文案残留"学习"(35处)/"默写"(约110处)
- 已确认决策（用户 08-13 选择）：
  - 创建 Trellis 任务跟踪
  - **深度结构整合**：学习/默写模块深度合并进关卡体系（改路由、抽共享组件、展示层映射）
  - 术语：**学习→历练、默写→默诵**

## 需求

### R1. 统一关卡工作区（深度整合核心）
- **R1.1** 篇目工作区 `/articles/:id/:tab` 成为唯一"关卡页"，5 个 tab 改为：**历练 / 鉴赏 / 考点 / 注释 / 默诵**
  - 历练 = 原文/译文/背诵引导（原 learn tab，文案改"历练"）
  - 默诵 = 默写训练（原 moxie tab）
- **R1.2** "默诵"tab **直接内嵌训练组件**（复用现有默写判分卡片逻辑，抽出为共享组件），不再是跳转入口卡；用户可在关卡页内直接做题判分，获得 XP/连击/关卡进度
- **R1.3** 默诵 tab 内含题型子导航（原文默诵/理解默诵/词义默诵/译文默诵），题型名做**展示层映射**（数据 json 不动）
- **R1.4** 关卡页保留"已答 x/y · 全对 z"进度、判分后 XP 飘字、错题自动入回炉簿等现有行为

### R2. 路由整合
- **R2.1** `/moxie/:id` → 重定向到 `/articles/:id/moxie`（旧链接/深链/测试兼容，不 404）
- **R2.2** `/moxie`（原默写列表页）保留为"默诵列表"页，文案全面改"默诵"
- **R2.3** `/moxie/errors`（原默写错题本）保留，改为"失误回炉"页
- **R2.4** 闯关地图 `/map` 关卡节点点击 → 关卡页默诵 tab（`/articles/:id/moxie`）

### R3. 首页游戏大厅化
- **R3.1** "今日学习"→"今日历练"，"已连续学习 N 天"→"已连续历练 N 天"
- **R3.2** "默写进度"环→"历练进度"（分母仍为默诵题总数）
- **R3.3** "默写错题回炉"→"失误回炉"；"开始默写"→"开始闯关"（指向 /map）
- **R3.4** 今日任务卡："默写 x/y 题"→"默诵 x/y 题"；"继续上次学习"→"继续上次历练"

### R4. 底部导航 TabBar
- **R4.1** 三 tab 文案：**历练(/) / 闯关(/map) / 成就(/achievements)**；激活逻辑不变

### R5. 全局文案与展示层映射
- **R5.1** 静态 UI 文案全局替换：学习→历练、默写→默诵（含 App header/footer、HeroStats、ArticleReader 背诵引导、EmptyState 提示、Moxie 系列页面、成就描述等所有用户可见处）
- **R5.2** 题型名展示层映射（数据 json 保持原值"原文默写"等，渲染时映射）：原文默写→原文默诵、理解性默写→理解默诵、词义默写→词义默诵、译文默写→译文默诵、名句默写→名句默诵
- **R5.3** 考点标签数据（exam-tags.ts 的"背诵默写"等）在展示层同样映射为"背诵默诵"等
- **R5.4** 提供中心化映射工具（如 `src/shared/lib/game-terms.ts`），数据驱动的文案统一走映射，静态文案直接改字
- **R5.5** 成就文案："完成第 1 道默写题"→"完成第 1 道默诵题"、"通关 5 篇默写"→"通关 5 个关卡"、"连续学习 N 天"→"连续历练 N 天"、"完成全部 129 篇默写"→"完成全部关卡"

### R6. 数据层与内部标识（边界）
- **R6.1** 数据 json 字段**不改**（moxie.json 的 type、qid、articleId 等保持原值）——构建管道零风险
- **R6.2** localStorage key（wyw_moxie_progress_v1 等）、qid 前缀（moxie-）、函数名、文件名**不改**（内部标识，用户不可见）
- **R6.3** 类型/代码注释中的"学习/默写"顺手更新为"历练/默诵"（低优先、低风险清理）

### R7. 测试同步
- **R7.1** 三套 playwright 测试同步更新：browser-test.mjs(67) / page-scan.mjs(85) / full-flow-test.mjs(44) 中所有"学习/默写"断言与路由断言改为新文案/新路由
- **R7.2** 新增断言覆盖：默诵 tab 内嵌训练可做题、/moxie/:id 重定向、关卡地图→关卡页跳转

## 验收标准

1. `grep -rn "学习\|默写" src/ --include="*.tsx"` 在**用户可见渲染路径**（JSX 文本、aria-label、title、占位符）为零；仅允许数据值文件（exam-tags.ts 原始数据、构建产物 json）与代码注释残留
2. 篇目工作区 5 tab 显示"历练/鉴赏/考点/注释/默诵"，默诵 tab 可直接做题并正常判分/加 XP/入库错题
3. 访问 `/moxie/:id` 自动落到关卡页默诵 tab，不出现 404
4. 闯关地图点击任意可玩/已通关关卡 → 进入对应关卡页默诵 tab
5. 首页显示"今日历练/历练进度/失误回炉/开始闯关"，TabBar 为"历练/闯关/成就"
6. App 页头页脚、成就墙、默诵列表、失误回炉页均无"学习/默写"字样
7. 题型显示为"原文默诵/理解默诵/词义默诵/译文默诵"
8. 回归全绿：`npm run typecheck` + `npm run validate`（或对应脚本）+ browser-test(67) + page-scan(85) + full-flow-test(44)
9. 生产构建 `npm run build` 通过，产物可部署
