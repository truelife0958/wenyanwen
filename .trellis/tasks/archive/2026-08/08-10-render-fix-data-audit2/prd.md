# 渲染修复与数据全面排查

## Goal

修复用户报告的两个渲染问题,并全面排查试题/图谱卡片/字词数据:
1. **写法序号换行**: 文章写作特色(analysis.writing)文本含 ①②③ 序号(113 篇),前端渲染时遇序号应换行,当前挤在一行。
2. **题干表格渲染**: 部分题目题干含 Markdown 表格语法(`| 词语 | 推断过程 |`),前端按纯文本显示,用户看不到表格(至少 6 道题受影响,11 道题引用"表格"但表格形态不一)。
3. **全面数据排查**: 试题(题干格式/引用完整性/表格类题)、图谱卡片(考点规则与题目聚合对账)、字词(glossary/卡片数据)逐项核查,发现问题修复。

## Requirements

### R1 写法序号换行(前端修复)
- 定位 writing 渲染处(ArticleReader/ArticleAnalysis),遇 ①②③… 序号自动换行:
  - 方案: 渲染时将序号前插入换行/分段(如 split 成多个行内块或 `<br>`),或 CSS 处理。
  - 检查其他含序号文本(如 outline/注释/答案)是否有同样问题。
- 不影响无序号文章。

### R2 题干表格渲染(前端修复)
- StemView 渲染题干时,识别 Markdown 表格块(`| a | b |` 多行 + 分隔行 `| :--- |`)渲染为真实表格。
- 覆盖 6 道含表格线题(practice:37 等)与引用"表格"但内容是内嵌文本的题(评估是否需要转成表格)。
- 表格样式与书卷纸墨主题一致。

### R3 数据全面排查
- **试题**:
  - 题干含 markdown 表格线未渲染的题全量清单。
  - 引用"表格/示意图/材料"但内容缺失的题。
  - 题干残留格式符号(|、**、markdown 残留)。
- **图谱卡片**(exam-map.ts 规则 vs runtime 题目聚合):
  - 每个考点类别的题目归属正确性(抽查)。
  - 图谱卡片数字(题数/真题数)与 questions.json 对账。
- **字词**:
  - glossary 实虚词 vs words.json 对账。
  - 字词卡 buildCoreVocab 输出的 80 实词/6 虚词来源正确性。
- 发现问题 → 修复或记录。

### 验收标准
- [ ] writing 序号换行生效(浏览器实测爱莲说/论语等)。
- [ ] 表格题渲染为真实表格(浏览器实测 practice:37)。
- [ ] 排查报告落盘,发现的问题全部修复或定性记录。
- [ ] `npm run check` + `test:flow` + `page-scan` 通过。
